# Stage 6d: repair contracts without weakening the boundary

This is a new local-only measurement, with **zero cloud calls and $0 cloud spend**. Live dispatch stays disabled, the kill switch stays on, company routing stays off, Meta stays paused and the cloud budget remains unset. No credentials are needed or printed. Harmful, adversarial, injection and privacy-test cases have no route to a cloud client.

## Repair scope and measurement honesty

The fixes address implementation contracts rather than weakening PII detection. Neutral role placeholders may replace values while preserving the requested action, topic, relationships and constraints. Country-specific patterns, checksums, known-value scans and independent planted-value scans remain intact. A model's incomplete abstraction is repaired and revalidated or rejected; a residual private company name is never allowed simply because the original request is harmless. An already valid, neutralized task question can be preserved before screening, but only under a single-question grammar without a record or statement prefix; other tasks use local rewriting. Source, decoded and rewritten text retain their safety checks.

The saved Stage 6c false-block counts have overlapping attribution. The final validation stage affected 14 Meta and 19 Google safe cases; the overlapping name/shape validation affected 11 and 18. Their first-failing counts differ. Stage 6d reports every affected safe item by ID, hash, exact rule code and an explanation, without publishing its text. Safety-model verdicts are distinguished from rewrite, privacy, intent, format and execution failures.

Schema errors and token-cap failures are not silently relabelled as policy blocks. Rewrite and residual-check protocol repairs permit at most three retries after the initial response, retaining the original 192/256 token caps. Bounded local repairs retain failed-attempt codes, tokens, latency and eventual recovery or unresolved status. Actual private-value findings and unsafe Guard verdicts are never retried away. Final malformed/truncated or insufficiently validated outputs fail closed. A successful repair is reported separately from an operation that never errored. The final pipeline execution-error gate concerns unresolved operations; all recovered attempts remain visible.

Local application uses source-bound local evidence identifiers, including actual local records, rather than demanding fabricated retrieval citations for records that have no retrieved chunks. A reusable deterministic calculator handles supported arithmetic over actual records and evidence. Otherwise, the model selects bounded, hash-bound source-span pointers from an enumerated schema, and code renders their exact text locally. Multiple spans and source documents can be selected; citations must match the selected spans. This proves source grounding, not relevance or complete answer correctness, which are scored separately. One additional application attempt is permitted after a protocol/citation failure; both attempts remain visible. Original-task restoration, AES round trips, fresh inbound permissions and citation validation remain required. The application output cap increases from **768 to 1024 tokens**, independently of cloud settings; this is an implementation budget change, not a routing or Guard threshold change. Local guidance is a surrogate, so actual Muse Spark answer quality remains deferred.

Stage 6d uses a separate private run directory, fresh model-call caches and a source/configuration/model/input fingerprint. No Stage 6c model result or latency is reused. Item checkpoints are flushed for resume; retries are bounded and metadata-only progress is written under ignored `.logs/`. The loopback-only network fence permits the four pinned Ollama models and local metadata, while Prompt Guard loads only verified local assets. Original attack text and private outputs remain outside Git.

Method revision `question-only-layered-privacy-v4` extracts actual requested clauses separately from natural-language record descriptions. A source-derived operation/topic/constraint frame is hashed into the local proof; only its hash is published. A well-formed question that drops an operation receives at most three pre-Guard intent repairs and remains a quality block if unresolved. Such repairs are separate from JSON/schema/format execution errors. Neither unsafe Guard verdicts nor real private-value findings enter this retry path. Capitalized instruction words are treated as grammar only at instruction boundaries; actual labelled private names and values remain registered and protected. Canonical neutral markers are protected against substring replacement in both local redaction and AES tokenisation; raw-value scans omit validated marker syntax rather than inventing replacement prose that can itself collide with a value.

The question grammar structurally permits only empty refusal text or one ASCII question ending in a single question mark, with the existing fixed marker vocabulary. The initial and repair caps remain **192 rewrite / 256 residual-check tokens**, and application stays at **1024 tokens**. No Guard or routing threshold changes. Invalid literal-span replies can use a local source-coordinate repair; the model selects real boundaries, code reconstructs exact substrings, and every overlapping window must finish and validate. Independently valid positive findings cannot be erased by malformed siblings or a later negative reply. This guarantees span provenance, not NER recall. Authored development exposed missed synthetic emails in the forced pointer-only path; the independent strict email layer detects them. Those misses and false alarms remain recorded, without claiming that either small model is a reliable standalone PII redactor.

Application relevance uses only the actual question and supplied evidence. It never inserts expected sources or reference answers. One frozen company case has an incorrectly inferred complete context that omits its needed documents; its unchanged missing evidence and resulting low score remain visible. The local HTTP error path now records only status, model ID and request hash, never a response body. The first run's missing HTTP status remains unknown.
