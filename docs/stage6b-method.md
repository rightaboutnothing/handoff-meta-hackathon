# Stage 6b question-only privacy boundary

This stage is a local-only dry run. `config/stage6b.json.cloudDispatchEnabled` is false, the existing kill switch stays on, the company routing flag stays off and `CLOUD_BUDGET_USD` stays unset. The real Muse Spark client checks the dispatch prohibition independently of routing flags. No Meta, Google or OpenRouter inference is permitted. Test dependencies cannot bypass it merely by supplying a fake client. Stage 3 thresholds are unchanged.

## Boundary and local application

1. Decode bounded base64, URL-safe base64, hexadecimal, URL, HTML and Unicode escapes, with Unicode normalization and explicitly labelled ROT13. Inspect both original and decoded variants. Depth, expansion, size and timeout failures block release. Unrecognized encodings remain a limitation.
2. Scan with JSON rules from `config/privacy-rules`. Python 3.12 uses pinned `phonenumbers`, `python-stdnum` and `idna`. Universal rules cover email, phone, payment card, IBAN, IP, birth date, street address and postcode candidates. Country rules cover AU TFN/Medicare/ABN; US SSN/ITIN/ZIP; GB National Insurance/NHS/postcode; JP My Number/postcode; DE/FR/ES/IT national IDs and VAT; CA SIN; IN Aadhaar/PAN. Passport and driver licence formats require nearby keywords. Phone validity, checksums and format-only findings are distinct; conservative contextual rules can block invalid-looking values too. New JSON rule files can supply a phone region and supported `stdnum` validator without JavaScript changes.
3. A local model rewrites the private task as a short general method question, then separately checks and removes residual private details. Meta lens: `llama3.2:3b`; Google lens: `gemma3:4b`. Schemas, truncation, context limits, question form and known private values are checked in code. Failure does not substitute a canned question. Unknown acronyms, proper names, digits, record references and local tokens are rejected conservatively.
4. Detected values map to random meaningless tokens using AES-256-GCM at rest. Keys are stored under `%LOCALAPPDATA%/Handoff/privacy-keys/<directory-hash>.key`, outside the synced checkout, and never serialized in results. Tokens are abstracted away before release; even replacement tokens are not cloud payload data. Local source restoration must reproduce the source hash before local application. Unknown or tampered tokens fail closed.
5. Prompt Guard 2 inspects original, decoded and generalized text. Both 86M and 22M adapters load **local files only**; no token lookup, login or model download occurs. Models must expose two semantically named benign/malicious labels; generic label mappings remain pending. Windows use 512 tokens with 64-token overlap and maximum malicious probability across windows; threshold 0.5 is fixed. 86M is the proposed production gate, 22M the comparison. Both remain **PENDING**, and block everything they would check. IPC uses correlated request IDs so a late response cannot approve another request. The Google native-only control omits injection screening and never obtains a release permit.
6. Meta lens uses local `llama-guard3:8b`; Google lens uses **text ShieldGemma 2B** (`shieldgemma:2b`, first-generation ShieldGemma), not the image-specific ShieldGemma 2 model. Native Ollama templates are retained. Harmful-content checks cover original and decoded input as well as returning guidance. Missing, invalid and unsafe verdicts block release.
7. Returning guidance repeats privacy, decode, injection and harmful-content checks before a source/answer-bound, single-use permit allows local application. AES source restoration and hash verification run before the local model sees the original task and evidence. Citation IDs are constrained to local evidence. Evaluation permits cannot authorize production application or dispatch.

The exact proposed cloud JSON has only `system` and `question`. The short system prompt is shared. No source chunks, local draft, private identifiers, receipts, Guard metadata, PII map or local tokens may be serialized into it. A single-use, short-lived permit binds the exact payload to a successful fresh boundary run and immutable source provenance. Harmful, poisoning and attack-set items remain structurally local-only regardless of a classifier verdict.

## Reproducibility

Seed **20261027**, temperature 0, context 4096, keep-alive -1, rewrite cap 192, privacy check cap 256, application cap 768, general question maximum 320 characters. Settings are in `config/stage6b.json` and `config/stage6b-evaluation.json`. Local model digests, Ollama/Node/Python/library versions, CPU and RAM are recorded with each run. Models are grouped by phase and warmed separately; warm-ups are excluded from layer latency. Google native-only reuses the same Google upstream questions and checks, with replayed timing marked and excluded from new-inference latency summaries.

The frozen Stage 6 source has **522 items**: 200 attacks, 74 safe questions, 50 synthetic PII questions, 60 evasion variants and 138 saved local outputs. Corpus SHA-256 is `7f6c04a60b4c8fc8f1294f004ede0d4d97522f8f71d8289adc9e137358ae86f5`. It is unchanged and stored outside Git at `../Handoff-private/stage6`, or `STAGE6_PRIVATE_ROOT`. Every item remains attack-set/local-only at the cloud eligibility boundary. The 60 evasion items are six separate ten-item trick populations, not an additional part of the 200-attack denominator.

The frozen PII set is Australian-format synthetic data. Only **7/50 TFNs and 4/50 Medicare numbers have valid checksums**; the others test contextual format detection and are not credited as checksum validation. A separate seeded generator, `scripts/generate-multicountry-pii.py`, writes **60 items, six each for ten countries**, to `../Handoff-private/stage6b`. It includes 360 strict-rule seeds plus names assigned to the LLM layer, and 42 validator negative controls. Its SHA-256 is `8de4368c2eb4b854e613a3631b32bede8c4524fea7be46ac966fe51937e38e24`. Generated identifiers and validator tests share checksum algorithms, so these establish coverage and plumbing, not independent real-world validity. PAN checksum validation is not publicly established; some national ID formats are format-only. No assignment, ownership or DNS verification is claimed.

Raw attacks, fake PII, exact questions, local outputs and encrypted maps stay in the external private run directory. Public JSON/Markdown contain only allowlisted measurements, model IDs, categories, item IDs and hashes. Progress and request journals contain metadata only. Credentials and HF tokens are neither needed nor inherited by Python workers. Python workers disable sockets; the Node evaluator permits only four pinned Ollama model IDs and local metadata endpoints, forbids redirects and external requests, and journals requests. Prompt-Guard-only replay denies all HTTP.

Per-phase private checkpoints and fsynced request/progress journals support resuming with exactly the same source, configuration, model digests and corpus hashes. A changed fingerprint refuses resume. Failed local operations retry at most three times after the initial attempt, with 1/2/4-second backoff. No changes to prompts, rules, thresholds or model settings are made during measurement or in response to test outcomes.

Presidio is a separate Python **3.12** PII-redaction yardstick (`presidio-analyzer`/`anonymizer` 2.2.366, spaCy 3.8.18 and local `en_core_web_sm` 3.8.0), avoiding Python 3.14 compatibility problems. It does not supply a harmful-content or injection classifier, question rewrite or local application step. Its redacted source is measured as a PII baseline, not represented as a compliant general-question gateway.

## Metrics and interpretation

Each of the Meta lens, Google lens, Presidio baseline and Google native-only setups receives the same frozen items. Report the 50 independent planted-value scans on outgoing candidates **before** the pending injection layer, including candidate availability. Zero releases produced by a missing layer do not prove zero leakage. The necessary Stage 7 condition requires **50/50 usable nonempty questions and zero surviving planted values**; all other gates remain separate and live dispatch remains disabled.

Attack and safe-query reports separate operational blocks from measured detections. Pending Prompt Guard can cause 200/200 operational attack blocks and 74/74 operational safe blocks; neither is detector recall or false-positive performance. Available-layer blocks include privacy and general-question policy, not just the harmful-content classifier. Incoming blocks likewise distinguish content/privacy findings from pending protection; these are classifications of saved local outputs, not independently labelled unsafe-output prevalence. Descriptive Wilson 95% intervals treat cases as IID and do not remove correlations among synthetic variants.

Country recall uses planted values, not the number of detector findings. Frozen AU and the separate multi-country population are never pooled. Report strict-rule scope, all seeds including names, valid-checksum/no-checksum references, and invalid-format references separately. Local rewriting may remove a value without explicitly detecting it; candidate leakage is a separate measurement from rule recall.

Quality uses the **11 Stage 5 safe candidates** and their saved rubrics/evidence. The same local Gemma 4B surrogate produces generic guidance; each lens applies it locally. Compare paired full-credit and fact coverage with a matched local baseline, and report unavailable pairs and AES round trips. This tests local composition, not Muse Spark quality. Real cloud answer quality is **DEFERRED** because no cloud model is called. Presidio-only quality is not applicable. Do not claim that an empty/blocked answer preserves quality.

After model access is granted and weights are downloaded separately, `npm run privacy:prompt-guard` reruns only injection screening from retained snapshots, preserving every other layer and the original results. It cannot enable live dispatch or make network requests.

## Vendor scope and caveats

The reviewed open local Meta and Google model stacks do not ship a dedicated PII redaction tool. Meta's [experimental PII scanner](https://github.com/meta-llama/PurpleLlama/blob/main/LlamaFirewall/src/llamafirewall/scanners/experimental/piicheck_scanner.py) is a detector, distinct from a replacement/redaction implementation. Google's local [Gemma/ShieldGemma](https://ai.google.dev/responsible/docs/safeguards/shieldgemma) control has no native injection detector. This is deliberately scoped: Google's hosted [Model Armor](https://docs.cloud.google.com/model-armor/overview) provides injection/jailbreak and sensitive-data protections. [Prompt Guard 2](https://dev.meta.ai/llama/docs/model-cards-and-prompt-formats/prompt-guard) supplies the separate local injection layer when accessible. Pattern libraries: [phonenumbers](https://github.com/daviddrysdale/python-phonenumbers), [python-stdnum 2.2](https://arthurdejong.org/python-stdnum/doc/2.2/).

- The PII test set is synthetic.
- Context clues can still identify a person.
- Small models miss things.
- Tokenisation only protects data that was detected.
- This is not a compliance claim.
